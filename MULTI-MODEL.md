# Independent critique, accountable synthesis

The purpose of multiple models is to expose blind spots through distinct analyses. Agreement across model outputs is not independent empirical evidence.

## One bounded cycle

1. Freeze a **public-only packet**: question ID, exact claim version/commit, definitions, consulted sources, and two or more live alternatives. Start with [R001](research/packets/R001-process-priority.md).
2. Obtain two independent critiques from **different actual models** with authorized tools. Initially withhold the other critique to reduce anchoring. Specify the same evidence budget and question. Where feasible, include a human disciplinary critic as a separate perspective.
3. Ask a synthesizer to compare the critiques, identify shared assumptions, retain dissent, and propose either a revision or a discriminating next test. Do not reward agreement with the preferred worldview.
4. Record verified model/provider/version and available reasoning settings; source access; date; tool limits; packet commit; and whether the reviewers saw one another's outputs. Never invent an inaccessible model identity or reasoning setting.
5. Publish a concise reviewed research artifact. Include external model output only when its use and publication are authorized. Exclude all personal context and conversation logs.

## Output format

Question and target version; strongest objection; alternative account; supporting sources; limitations; proposed revision; evidence or argument that would reverse the assessment; disagreements retained.

## Honest states

- `packet-ready`: a bounded public question exists.
- `awaiting-independent-review`: an additional real model has not been run.
- `reviewed`: distinct reviews exist with verified provenance.
- `synthesized`: a comparison and its unresolved tensions are recorded.
- `integrated`: a reviewed change links back to the critique.

A single model playing several roles is a useful rehearsal, but must be labeled `single-model role exercise`, never multi-model validation. No automatic paid API calls, external service connections, or additional permissions are enabled by this document. Honor configured budgets and repository-only access.
