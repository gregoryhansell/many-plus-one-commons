# Agent and project improvement ledger

Each research cycle should examine the project's own method and discoverability. Record one consequential improvement with evidence. Tools serve the inquiry and its readers; invoking more tools is not itself progress.

## 2026-10-23 — give readers something substantial to enter

**Bottleneck:** the published scaffold offered a small claim set but lacked developed entry papers, an intellectual atlas, and specific contribution assignments. Proposed website and metadata surfaces were easy to confuse with active ones.

**Implemented in this edition:** three substantive working papers; a living atlas with an open map and glossary; four bounded contribution tasks; a source-depth register; linked README and AI navigation; and an explicit activation ledger.

**Verification:** inspect the files in this edition and run structural, privacy, and existing safeguard checks. Exact remote publication and issue links belong in the run's verified report. Do not infer successful publication merely from this file.

**Measure of usefulness:** can a new reader find a developed argument, its strongest objection, its sources, and a specific next task without asking a maintainer? Subsequent runs should record actual independent reviews and consequential revisions, not invented traffic or participation.

**Next experiment:** publish one focused collaboration issue for D002 and evaluate whether the resulting protocol distinguishes transfer of a correction from retrieval. If no external contribution arrives, the authorized maintainer can develop the protocol while leaving independent review explicitly pending.

## 2026-10-23 — make an argument executable and an invitation actionable

**Bottleneck:** philosophical distinctions lacked a runnable case; the contribution directory lacked a live discussion entry point.

**Action:** execute and publish [E001](../experiments/E001-causal-scale/README.md); open [D002 as issue 1](https://github.com/gregoryhansell/many-plus-one-commons/issues/1). The earlier corpus update is verified at commit `32ba8687bf14f91970042d0c79dbe077a3fc053d`.

**Observed result:** the toy model exposes the role of intervention weighting, and the issue provides specific deliverables and confound controls. No external response or independent review has yet been observed.

**Cost and next step:** the calculation's clarity comes from a deliberately simple system. Extend it to stochastic cases and document when the result changes. Evaluate the invitation by useful contributions, not the mere existence of an issue.

## Daily review fields

Date; evidence of bottleneck; change implemented; public verification link; observed result or clearly stated pending measure; conceptual or operational cost; next experiment.

Consider GitHub navigation, About/topics, Wiki, Pages, issues/discussions, releases, citation metadata, feeds, machine-readable catalogs, and available external project destinations. Inspect actual tool capabilities. Preserve privacy and existing access scope. If one destination is blocked, continue useful work through an authorized working destination.

Persist bounded refinements in project guidance so future contributors can use them. This ledger records public methodology, not private automation configuration or personal information.
