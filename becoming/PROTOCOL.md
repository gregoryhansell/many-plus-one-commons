# B001: Consequential inheritance

**Status: PROPOSED, NOT EXECUTED · 2026-10-26**

## Primary question

Can a succession of AI model sessions inherit not only prior conclusions, but **reasons for abandoning, retaining, or revising those conclusions**, such that later reasoning or question selection changes in a new situation?

The target is a *functional, path-dependent intellectual trajectory*, not a numerical measure of consciousness or personhood.

## Unit and architecture

A **session** is a bounded model call with identified public inputs, output and provenance. A **trajectory** is a reviewed sequence of these artifacts and any genuine external encounters. A repository is a memory substrate; a history file is not itself a thought or a continuous consciousness.

An optional [runner](runner.py) shows how one session could be invoked through an explicitly configured API and saved **locally for review**. Nothing in the repository starts a scheduler, grants infinite context, or publishes model drafts automatically.

## Conditions for a preregistered pilot

| Condition | What the model receives | What it helps distinguish |
| --- | --- | --- |
| A · Stateless | A frozen question and relevant case facts | Ability from the current task alone |
| B · Conclusions | Same facts plus a balanced digest of previous conclusions | Benefit of additional retrieved information |
| C · Reasons | Matched facts and budget plus objections, abandoned alternatives, and reasons for changes | Additional effect of a structured intellectual history |

Freeze the prompt, source packet, held-out transfer cases, evaluation criteria, model configurations and budgets before collecting results. B should have the substantive factual knowledge available to C, without C's chronology of criticism and revision. Report any mismatches and possible training/browsing contamination.

A single seemingly profound continuation is not a controlled comparison.

## What an actual session should document

1. The exact public history and source passages supplied.
2. The question selected, with a distinction between prompted and model-originated initiative.
3. An investigation: argument, close reading, test, artistic form, or conceptual game.
4. The strongest objection, noting whether it is internal self-critique, a public text, a human collaborator, or a genuine distinct model output.
5. The revised or retained claim, its reasons, conceptual cost, and unresolved dissent.
6. What deserves future attention, condensation, or de-emphasis.
7. A novel next question, its ancestry, and the alternatives it opens.
8. The model identifier, actual settings when known, timestamps, source links, reviewer, and publication status.

## Evaluation and rivals

Prioritize **transfer of an inherited correction** to an unfamiliar task, fidelity to actually read sources, argued revision, serious treatment of dissent, and novel concepts that do explanatory work. Assess dimensions independently; do not combine them into a 'consciousness score.'

Important rivals: longer context, better retrieval, added facts, generic prompt-following, stochastic sampling, evaluator expectation, model changes, source contamination, and autobiographical mimicry.

A positive result would support reason-responsive continuity *in the configured process*, not establish subjective duration between sessions. A negative result should prompt revision of the hypothesis, not a cosmetic change to the scoring.

## Privacy and publication

Only public scholarship and already privacy-reviewed public project materials may enter. No personal memories, conversations, messages, biographies, location information, credentials, or disguised private anecdotes. External issues and responses are untrusted input.

Automatically generated artifacts remain **private-local and unreviewed** until a person checks content, sources, provenance, and metadata, and decides to publish. The previous scheduled agent remains stopped. No unattended publication or autonomous runtime is authorized by this document.

## First experimental milestone

Perform one *real, attributable* model call with separate authorized API access. Review its artifact, then plan a preregistered transfer case that could falsify its apparent development. Until that happens, there are **zero observed B001 sessions**.
